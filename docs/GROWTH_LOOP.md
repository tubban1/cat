# 数据驱动增长闭环

目标不是“把游戏做完”，而是建立一个会持续学习的系统。

## 两种反馈

### 显式反馈
只在合适的失败轮次采样，不在每一局骚扰用户：
- 😴 太简单
- 😼 刚刚好
- 😾 不公平
- 可选一句话

### 隐式行为反馈
更重要的数据：
- page_view / first_interaction / game_start
- fake_cue / eyes_open / look_survived
- fish_stolen / run_end / retry
- share_open / share_complete
- challenge_copy / challenge_open / challenge_beat
- leaderboard_open / leaderboard_scope
- page_hide

## 所有不确定设计都实验化

第一批实验：
- A：预警更短、假动作较少
- B：预警稍长、假动作更多

主要指标：同一玩家是否愿意马上再开第二局。
增长指标：是否分享或发起好友挑战。
护栏指标：明确反馈“不公平”的比例。

## 自动优化

每天 GitHub Actions 自动分析最近 7 天。

只有当：
- 每个版本至少 200 个独立 session；
- 领先版本的不公平反馈率没有超过阈值；
- 综合差异达到最小效果量；

才会自动把实验流量从 50/50 调整为 75/25。

双方都超过 1000 个 session 且优势更明显时，最多调整到 90/10。

永远不自动变成 100/0，始终保留探索流量。

## 变现顺序

1. 先获得自然流量
2. 提高二次开局率
3. 提高好友挑战带来的新增玩家
4. 找到稳定的短视频/分享素材
5. 再测试变现

第一批用户不建议强制插屏。未来优先实验：
- 死亡后自愿看广告换一次续命
- 每 4–6 局的自然断点广告
- “今日猫咪”品牌赞助
- 宠物用品联盟/电商导流

每一种变现都必须独立 A/B，护栏指标是二次开局率、session 长度、分享率和负面反馈。
